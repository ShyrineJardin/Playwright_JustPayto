## ❓ Common Questions & Answers

### Q: The browser won't open
**A:** 
1. Check the command window - it should say "Test Runner started"
2. Wait 10 seconds (it's starting the server)
3. Manually open browser and go to: `http://localhost:3000`
4. If still no luck, restart the `.bat` file

### Q: I see an error message
**A:** Look at the red text in the output:
- **"credentials expired"** → Ask admin to update `.env` file
- **"Element not found"** → Website layout may have changed, ask developer
- **"timeout"** → Website too slow, try again later
- **"email not found"** → Email server delay, tests check after 30 seconds

### Q: Can I run multiple tests at the same time?
**A:** No, but you can run them one after another:
1. Wait for first test to finish (check for ✅ or ❌)
2. Click "Clear Output" to clean the screen
3. Select a different test
4. Click "Run Test" again

### Q: How do I stop a running test?
**A:** 
1. Click the **"⏹️ Stop Test"** button
2. Test stops immediately
3. You can then run another test

### Q: Can I see test results in more detail?
**A:** Yes! After test runs:
1. Check the output panel for pass/fail message
2. Click "Help & Tips" tab for more information
3. Ask your admin to show you the `playwright-report` folder (detailed HTML reports)

### Q: What if I make a mistake selecting a test?
**A:** No problem!
1. Just select a different test from the left panel
2. Click "Run Test" to run the new one
3. The previous test is abandoned

### Q: What credentials do I need?
**A:** None! Tests use predefined test data:
- Test email addresses
- Test credit cards (that don't actually charge)
- Test merchant accounts
- All configured by the IT team ✅

# 📧 Gmail API Setup Guide for Email Testing
This guide explains how to add new email accounts for automated testing using Gmail API with multiple OAuth credentials.

## Overview
Each Gmail account requires its own OAuth credentials. Follow these steps to set up a new email account for testing.

### Step 1: Environment Configuration

#### 1.1 Add Email to .env File
Declare the new email account with a descriptive variable name:

```powershell
#Emails
INDIVIDUAL_MERCHANT_EMAIL=fpz.test1@gmail.com
```

#### 1.2 Update playwright.config.js
Add the environment variable to your Playwright configuration:

```powershell
//merchant email
INDIVIDUAL_MERCHANT_EMAIL:process.env.INDIVIDUAL_MERCHANT_EMAIL,
```

### Step 2: Gmail API Credential Paths
Add credential and token file paths to helpers/gmail-helpers.js:

````javascript
// Gmail credentials paths for individual accounts
const credentialPathIndividualUser = path.resolve(process.cwd(), 'playwright_individual_user.json');
const tokenPathIndividualUser = path.resolve(process.cwd(), 'playwright_individual_token.json'); // this file will be generated after step 4
````

### Step 3: Create OAuth Credentials in Google Cloud Console

#### 3.1 Go to Google Cloud Console
Navigate to Gmail API Credentials

#### 3.2 Create OAuth 2.0 Client
1. Click "Create Credentials" → "OAuth client ID"

2. Select "Desktop App" as Application type

3. Enter a descriptive name (e.g., "Individual Merchant Email")

4. Click "Create"

#### 3.3 Download Credentials
1. Download the JSON file from the credentials dialog

2. Click "OK" to close the dialog

3. Rename the downloaded file to match your credential path (e.g., credentials-individual-merchant.json)

4. Place the file in your test folder root directory

### Step 4: Generate Authentication Token
Run the following command to generate the authentication token in terminal:

```powershell
node node_modules/gmail-tester/init.js file_name.json file_name_token.json used_email_address@gmail.com
```

Example:

```powershell
node node_modules/gmail-tester/init.js playwright_individual_merchant.json playwright_individual_merchant_token.json fpz.test1@gmail.com
```

Parameters:
- credentials-individual-merchant.json - Your downloaded credential file
- token-individual-merchant.json - Token file to be generated
- fpz.test1@gmail.com - The Gmail account from Step 1

#### 4.1 Authorize Application
1. A browser window will open
2. Select the Gmail account that matches your configuration
3. Click "Continue" through the authorization prompts
4. Grant the necessary permissions
5. After authorization, the token file will be created in your project root

### Step 5: Configure Task

Add a custom Gmail check task in helpers/gmail-helper.js:

Example:

```javascript
export async function checkEmail(options) {
  const {
    from,
    to,
    subject,
    wait_time_sec = 20,
    max_wait_time_sec = 120,
    after
  } = options;
 
  try {
    console.log('🔍 Checking Gmail inbox...');
    console.log(`   From: ${from}`);
    console.log(`   To: ${to}`);
    console.log(`   Subject: ${subject}`);
    console.log(`   After: ${after || 'any time'}`);
    console.log(`   Wait time: ${wait_time_sec}s, Max: ${max_wait_time_sec}s`);
   
    // Determine which credentials to use based on recipient email
    let credentialPath, tokenPath;
   
    // Check if this is a business user email (fpztest.sjardin@gmail.com)
    if (to === process.env.BUSINESS_USER_EMAIL) {
      console.log('📧 Using BUSINESS USER credentials (reusing Individual Merchant creds)');
      credentialPath = credentialPathBusinessUser;
      tokenPath = tokenPathBusinessUser;
    }
    // Default to individual user credentials (fpz.test1@gmail.com)
    else {
      console.log('📧 Using INDIVIDUAL USER credentials');
      credentialPath = credentialPathIndividualUser;
      tokenPath = tokenPathIndividualUser;
    }
   
    // Convert ISO string to Date if provided
    const afterDate = after ? new Date(after) : undefined;
   
    const email = await gmail.check_inbox(
      credentialPath,
      tokenPath,
      {
        subject: subject,
        to: to,
        from: from,
        include_body: true,
        wait_time_sec: wait_time_sec,
        max_wait_time_sec: max_wait_time_sec,
        after: afterDate
      }
    );


    if (email) {
      console.log('✅ User email found');
      console.log(`   Subject: ${email.subject}`);
    }
   
    return email;
  } catch (error) {
    console.error('❌ Gmail check error:', error.message);
    return null;
  }
}
```

## Troubleshooting

### Token Expired:
1. Re-run the token generation command (Step 4)
2. Delete the old token file before regenerating

### Email Not Found:
- Verify the subject, to, and from parameters are correct
- Increase max_wait_time_sec to allow for email delays
- Check the after timestamp allows enough time buffer
- Confirm the email account has the necessary Gmail API permissions

### Credentials Error:
- Ensure credential and token file paths are correct
- Verify files exist in the specified locations
- Check that the credential file matches the email account

## Best Practices
1. Use descriptive variable names for each email account
2. Set appropriate time buffers when searching for emails (30 seconds before trigger)
3. Validate email timestamps to avoid false positives from old emails
4. Handle errors gracefully with clear error messages
5. Keep credentials secure and never commit them to version control

## Performance Considerations

### Page Load Timeouts
- Page navigation: **90 seconds** (with `waitUntil: 'domcontentloaded'`)
- Element visibility: **60 seconds**
- Network requests: **30 seconds**
- Email verification: **180 seconds** (with retry)

These generous timeouts are necessary for:
- GUI execution overhead (PowerShell spawn)
- Slow network conditions
- Email server delays
- Website latency

### Test Duration by Type
| Test | Duration | Reason |
|------|----------|--------|
| Individual Payment | 3-5 min | Form fill + payment + email |
| Business Payment | 4-6 min | Additional validation |
| Donation | 3-4 min | Simpler flow |
| Multi-Biller (Bayadcenter) | 4-5 min | Biller selection + payment |
| AutoSweep | 2-3 min | Simple RFID flow |

### Optimization Tips
1. Use headless mode (no browser rendering) for ~20% speed increase
2. Run tests during off-peak hours when website is faster
3. Use Chromium (default) - it's the fastest browser
4. Don't run too many tests concurrently (limits: CPU, memory, connections)

## Troubleshooting Implementation Issues

### Issue: Port 3000 Already In Use
**Cause**: Another app using port 3000
**Solution**:
```powershell
# Find and kill process on port 3000
netstat -ano | findstr :3000
taskkill /PID [PID] /F

# Or change port in test-runner.js
const PORT = 3001; // Instead of 3000
```

### Issue: Tests Not Finding Environment Variables
**Cause**: `.env` file not in project root
**Solution**:
```powershell
# Verify .env exists
Test-Path .\.env

# If not, create it:
# 1. Open Notepad
# 2. Add variables
# 3. Save as: Playwright_JustPayto\.env (not .env.txt)
```

### Issue: Browser Won't Launch
**Cause**: Playwright browsers not installed
**Solution**:
```powershell
npx playwright install --with-deps
```

### Issue: Tests Timeout
**Cause**: Slow website or network
**Solution**:
1. Increase timeouts in test files (already set to 90s/60s)
2. Test during off-peak hours
3. Check website is up: https://dev.justpay.to

# 🐛 Troubleshooting

## Problem: Tests Pass Locally but Fail in GitHub CI/CD

### Possible Causes & Solutions:

1. **Environment Variables Not Set**
   - Go to: GitHub repo → Settings → Secrets and variables → Actions
   - Add all variables from your `.env` file as secrets
   - Names must match exactly

2. **Different Test Environment**
   - GitHub uses Linux (not Windows)
   - Some tests may behave differently
   - Check `.github/workflows/playwright.yml` configuration

3. **Timeout Issues in CI**
   - CI servers are slower
   - Timeouts already set to 90/60 seconds (generous)
   - If still failing, increase in playwright.config.js
